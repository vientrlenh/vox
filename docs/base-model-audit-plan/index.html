Base model, audit actor, builders and entity packages

Repository: vox · Branch: default · Written 2026-11-21 · Plan status: Draft

Today every domain model and every JPA entity repeats id, createdAt, updatedAt, createdBy and updatedBy by hand, the use cases stamp them (263 setCreated*/setUpdated* calls), ids come from the Postgres uuidv7() default, and every class carries hand-written accessors and positional constructors. This plan introduces a shared BaseModel (domain) and BaseEntity (persistence); makes createdBy/updatedBy a String that a JPA auditing hook fills with the acting user's id or "System"; moves id generation to Hibernate @UuidGenerator(style = VERSION_7); gives every domain model a hand-written nested Builder; replaces the hand-written accessors of the entities with Lombok; and regroups the 107 entities into feature packages that mirror domain/model. It is worth doing because new audit rules, id rules and construction rules then change in one place instead of in about 100 classes and 150 use cases.

This plan goes beyond AGENTS.md. The repository is in the refactoring stage, and AGENTS.md says to stop and ask when a task goes against it. The parts that do are listed in section 1 ("Where this plan leaves AGENTS.md") and are asked as decision D1. Nothing in Phase 1 or later may start until D1 is answered. D6. How are createdAt/updatedAt/createdBy/updatedBy filled automatically? Answered

You asked for an interceptor. Both options fill the values on persist and update, and both run the update hook at flush time, not at save() (see the risk about stale updatedAt in the returned object).

A. (recommended) Spring Data JPA auditing (the framework's own mechanism for Spring Data JPA 4.1): @EnableJpaAuditing, AuditingEntityListener on BaseEntity, @CreatedDate/@LastModifiedDate/@CreatedBy/@LastModifiedBy, and an AuditorAware<String> that returns the user id or "System". Design that is decided by this plan (not asked)

  • Actor value. createdBy/updatedBy hold userId.toString() for a logged-in caller and "System" (ActorConstant.SYSTEM) otherwise: schedulers, Kafka consumers, anonymous endpoints. Column type varchar(64). Existing rows are converted with USING created_by::text; NULLs stay NULL (no data is invented), so readers must accept NULL, "System" and a UUID string.
  • Builder shape. Each model gets a nested public static class Builder plus public static Builder builder() { return new Builder(); }. The builder holds the model instance created by the no-argument constructor, each fluent method sets one field and returns this, and build() returns the instance, so no method grows with the field count (the largest model has 26 fields). Audited models extend a shared self-typed BaseModel.Builder<T extends BaseModel, B extends BaseModel.Builder<T, B>> that supplies id/createdAt/updatedAt/createdBy/updatedBy/build() once, instead of repeating five methods in 36 builders.
  • Helpers on BaseModel. createdByUserId(), updatedByUserId() (Optional<UUID>, empty for NULL, "System" or a non-UUID) and isCreatedBy(UUID). All ownership checks, quota reads and DTO mapping go through them, so the string-to-UUID rule exists once.
  • Entity annotations. Audited entities extend BaseEntity (@MappedSuperclass). Database-generated non-audited entities declare @Id @UuidGenerator(style = UuidGenerator.Style.VERSION_7) themselves; the 17 application-assigned ids stay as they are. The table defaults DEFAULT uuidv7() remain in the database.
  • Migration per batch. Because of ddl-auto: validate, each batch phase ships its own V<next>__<batch>_audit_actor_text.sql (next = highest + 1 at the time, V15 for the pilot) that converts created_by/updated_by of that batch's audited tables.
  • New ids in tests. A new entity must be saved with a null id: with a generated id a non-null id makes Spring Data call merge instead of persist. Fixtures that preset ids on new entities are fixed in the batch that converts them.

package com.sep.vox.domain.model;

import java.time.Instant;
import java.util.Optional;
import java.util.UUID;

/**
 * State shared by every domain model that is stored with an id and audit columns.
 *
 * <p>{@code createdBy} and {@code updatedBy} hold the acting user's id as text, or
 * {@link com.sep.vox.domain.common.ActorConstant#SYSTEM} when no user performed the change. The persistence layer fills
 * all four audit values when the record is saved; use cases and factories do not set them. Rows written before this
 * convention can still hold {@code null}.
 */
public abstract class BaseModel {

    private static final int UUID_TEXT_LENGTH = 36;

    private UUID id;
    private Instant createdAt;
    private Instant updatedAt;
    private String createdBy;
    private String updatedBy;

    public UUID getId() {
        return id;
    }

    public void setId(UUID id) {
        this.id = id;
    }

    public Instant getCreatedAt() {
        return createdAt;
    }

    public void setCreatedAt(Instant createdAt) {
        this.createdAt = createdAt;
    }

    public Instant getUpdatedAt() {
        return updatedAt;
    }

    public void setUpdatedAt(Instant updatedAt) {
        this.updatedAt = updatedAt;
    }

    public String getCreatedBy() {
        return createdBy;
    }

    public void setCreatedBy(String createdBy) {
        this.createdBy = createdBy;
    }

    public String getUpdatedBy() {
        return updatedBy;
    }

    public void setUpdatedBy(String updatedBy) {
        this.updatedBy = updatedBy;
    }

    /** The creating user's id, or empty when the record was created by the system or the value is unknown. */
    public Optional<UUID> createdByUserId() {
        return toUserId(createdBy);
    }

    /** The last updating user's id, or empty when the last update was made by the system or the value is unknown. */
    public Optional<UUID> updatedByUserId() {
        return toUserId(updatedBy);
    }

    public boolean isCreatedBy(UUID userId) {
        return userId != null && userId.toString().equals(createdBy);
    }

    private static Optional<UUID> toUserId(String actor) {
        if (actor == null || actor.length() != UUID_TEXT_LENGTH) {
            return Optional.empty();
        }
        try {
            return Optional.of(UUID.fromString(actor));
        } catch (IllegalArgumentException notAUserId) {
            return Optional.empty();
        }
    }

    /**
     * Fluent builder of the shared fields. A subclass builder adds its own fields and passes the model it fills to
     * the constructor. A builder is single use: {@link #build()} returns the instance it has been filling, not a copy.
     *
     * @param <T> the model being built
     * @param <B> the concrete builder, so shared setters can return it and chaining keeps its type
     */
    public abstract static class Builder<T extends BaseModel, B extends Builder<T, B>> {

        protected final T target;

        protected Builder(T target) {
            this.target = target;
        }

        protected abstract B self();

        public B id(UUID id) {
            target.setId(id);
            return self();
        }

        public B createdAt(Instant createdAt) {
            target.setCreatedAt(createdAt);
            return self();
        }

        public B updatedAt(Instant updatedAt) {
            target.setUpdatedAt(updatedAt);
            return self();
        }

        public B createdBy(String createdBy) {
            target.setCreatedBy(createdBy);
            return self();
        }

        public B updatedBy(String updatedBy) {
            target.setUpdatedBy(updatedBy);
            return self();
        }

        public T build() {
            return target;
        }
    }
}

3. Phases

Each phase is independently reviewable and leaves the build green at its end. Inside a phase a job may not compile on its own, because a model change and its mapper are one slice.                                                                                                                                 4. Risks

                                                                                                                                • Blast radius. About 210 classes, 337 main + 342 test model construction sites with arguments (141 + 110 of them for audited models), 263 manual audit calls and 109 + 66 entity construction sites change. The plan limits it by phases of one package group, a pilot that fixes the recipe first (job 3.5), and a green compile at the end of every phase. Jobs inside a phase may not compile on their own, because a model change and its mapper are one slice.
                                                                                                                                • Stale updatedAt after save(). The update hook runs at flush, not at save(). The adapters map the object returned by save() back to a model, so a use case that returns it may show the previous updatedAt/updatedBy (today the use case sets them before saving). Job 3.4 measures this on the pilot. If a flush or re-read is needed, that is a behaviour change and is raised before the batches start.
                                                                                                                                • Preset ids on new entities. With a generated id, Spring Data treats a non-null id as an existing entity and calls merge. Test fixtures that preset ids on new entities, and any adapter that does so, must pass null; the 17 application-assigned entities are not affected.
                                                                                                                                • createdAt is always overwritten on insert. The auditing hook sets it at persist, so code that deliberately sets an earlier createdAt (imports, backfills) would lose it. Each batch greps for a createdAt that is not Instant.now() and reports it.
                                                                                                                                • Lost actor on threads without a security context. Schedulers, Kafka consumers and anonymous endpoints now write "System" (intended). Import commits are the one flow where a user started the work; D5 covers it. Other executors in AsyncConfig were not audited for context propagation (not checked); the batches that touch entities written from them check it.
                                                                                                                                • Bulk updates bypass the hook. @Modifying JPQL and native statements do not fire entity listeners. 19 repository files mention updated_at/updatedAt; one statement sets it with SET. They keep their manual values and are listed in Out of scope.
                                                                                                                                • Slice tests. @RepositoryTest and the web slices do not scan @Configuration. If auditing is not imported, created_at NOT NULL fails in repository tests; job 1.5 prevents it and job 1.3 checks the web slices.
                                                                                                                                • Lombok on entities. @SuperBuilder requires every class of a hierarchy to use it; @Data, @EqualsAndHashCode and @ToString are banned on entities (lazy state, mutable hash keys). Boolean fields named isActive generate isActive()/setActive(), matching today's accessors; the compiler flags any mismatch.
                                                                                                                                • Docker is not available here. Every database check (validate against the migrations, auditing tests, repository tests) is written as a command but was not run while planning; CI (./gradlew clean build --no-daemon) or a machine with Docker must run them before a phase is called done.
                                                                                                                                • Data semantics. After this plan an audit column holds a UUID string (old rows and logged-in actors), "System" (new system writes) or NULL (old system writes). Anything that parses the column as a UUID breaks on "System"; createdByUserId() is the only sanctioned parser.

                                                                                                                                5. Out of scope

                                                                                                                                • Regrouping repository, mapper, adapter and query packages by feature. Only entities were requested.
                                                                                                                                • The 17 entities with application-assigned ids (UUID.randomUUID(), version 4) keep their ids and adapters; they get no @UuidGenerator.
                                                                                                                                • Dropping DEFAULT uuidv7() from the tables (a native INSERT into notification_devices relies on it, and it is a harmless safety net).
                                                                                                                                • Adding audit columns to tables that lack them, and backfilling old audit values (D2 = A). Old NULLs stay NULL, old UUIDs stay text.
                                                                                                                                • Making models immutable, or removing model setters or the public no-argument constructor (the builder needs it; new <Model>() is used 9 times in main and 348 times in tests).
                                                                                                                                • Builders for DTO records, commands, queries and value objects; GraphQL or REST schema text changes (D4 = A).
                                                                                                                                • Hand-set updated_at in native or @Modifying statements (for example SpringDataSchoolBalanceRepository.insertIfAbsent).
                                                                                                                                • Changes to SecurityConfig, JWT/OAuth code, executors in AsyncConfig, Kafka topics, event payloads or env vars.
                                                                                                                                • Converting hand-written Mockito tests to @InjectMocks, translating comments in files this plan does not touch, and any other drive-by cleanup.
