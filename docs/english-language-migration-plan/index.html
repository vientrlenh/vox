Translate Vietnamese messages and comments to English

Repository: vox · Branch: default · Written 2026-11-27 · Plan status: Approved

1,518 Java files (plus configuration, GraphQL schemas and resources) still contain Vietnamese: about 6,700 comment lines and 6,300 string-literal lines. This plan moves the code to English in 12 phases, each of which leaves the build green and can be reviewed (and merged) on its own. Messages: the texts the code writes to logs and returns to API clients become English; texts that are data (seed content, import column aliases, test fixtures) stay, and what exactly counts as a “message” is decision D1. Comments: a comment that breaks the AGENTS.md “Self-explaining code” rule is deleted, every other comment is translated faithfully (decision D2, already made).

Facts that shape the plan

  1. Exception text is part of the API. GlobalExceptionHandler passes e.getMessage() into ErrorResponse for duplicated, not-found, illegal-argument, unauthorized, forbidden, business-rule, service-unavailable and disabled-user errors (lines 75–246), and GlobalExceptionResolver does the same for GraphQL (line 38). GlobalGrpcExceptionHandler has 2 Vietnamese status texts. Who reads these texts outside this repo (frontend, desktop app, AI grading service) is not checked.
  2. Some Vietnamese literals are input, not output. FileProcessingService from line 269 on maps column headers in uploaded Excel files ("mã lớp", "ho ten", ...) to fields, and RubricCriterionImportCommitHandler:344 accepts "có" as “yes”. Translating them would make real uploaded files fail.
  3. Some are seed data. 10 initializers (infrastructure/initializer, 506 string lines) write Vietnamese names and descriptors into the database. Whether they upsert by that text was not checked.
  4. Migrations are frozen. AGENTS.md says never edit a merged migration, and application.yaml lines 71–75 record that Flyway then refuses to start with “Migration checksum mismatch”.
  5. Method size counts comment lines. MethodLengthScanner measures from the return type to the closing brace, so a longer English comment inside a method body can push a 25-line method over the limit; and a method on method-size-exemptions.txt (6 entries) that gets short enough fails MethodSizeConventionTests until its entry is removed.
  6. Comment shapes (counted with regular expressions over comment runs): 43 runs start with a step number (the // 1. Validate the user pattern AGENTS.md forbids), 48 are banner lines (// ---- ... ----), 7 contain a fully qualified {@link ...}, and none looks like commented-out code. In a hand-read random sample of 45 runs, 1 clearly restated the code (// Xóa Assessment Policy của một trường học (School Admin) above deleteSchoolAssessmentPolicy), 2 were borderline, and 42 recorded a reason, a contract or an invariant. So most comments are translated and deletions are a minority; the exact ratio is not measured.
  7. Files AGENTS.md puts under “Ask first”. Security, JWT and OAuth code: 18 main files (SecurityConfig, infrastructure/security/* 5, infrastructure/filter/* 2, GoogleIdTokenProperties, GoogleIdTokenVerifierPort, VerifiedGoogleIdentity, StreamingServiceTokenInterceptor, OAuth2AuthenticationSuccessHandler, and the use cases GoogleTokenLogin, Login, Logout, OAuth2Login, Refresh). Money code (orders, payments, quota, school balance): 177 files by file-name match (158 main, 19 test), holding 1,476 comment lines, 22% of all Vietnamese comment lines. The match is by name, so it is approximate.
  8. Baseline is green. ./gradlew compileJava compileTestJava succeeds (15 s); ./gradlew test runs 2,823 tests in 479 classes with 0 failures, 0 errors (1 min 22 s). Docker is not running on this machine, so integrationTest was not run and cannot be run here.
  9. Other work in flight. test-restructuring-plan has phases 4 and 5 in progress (they edit tests under application/usecase). Four local refactor/* branches are not merged into default; whether they have open pull requests was not checked (it needs a call to GitHub).
  10. No formatter or linter (no Spotless, Checkstyle, PMD) is configured in build.gradle, and 5,129 lines in src/main/java already exceed 120 characters, so line wrapping is free except for the method-size rule above.

D1. Which Vietnamese string literals are translated? Answered

Four kinds of literal exist. A, developer-facing: log messages and IllegalStateException texts. B, API-visible: exception messages returned by the REST, GraphQL and gRPC handlers, Bean Validation messages, ApiResponse success messages, import row errors, OpenAPI annotation text, GraphQL schema descriptions. C, rendered content: email subjects and bodies (SmtpEmailTemplateRenderService and 9 templates), push notification titles and bodies, Excel export/template headers and sheet names. D, data (always stays Vietnamese): seed data, import header aliases and accepted values, the 'đ' char literals, Vietnamese names and transcripts in test fixtures.

A. (recommended) Translate A and B; keep C and D. The code speaks English to developers and API clients, while what end users read in emails, pushes and spreadsheets stays Vietnamese until someone decides how to localise it. Cost: any client that shows or matches an error message now sees English; the frontend, desktop app and AI grading service are outside this repo and were not checked, so the final report lists the changed channels (REST ErrorResponse.message, validation maps, ApiResponse.message, GraphQL errors, gRPC status text).

B. Translate A only. Nothing a client receives changes, so there is no cross-system impact and the AGENTS.md Language bullet stays correct as written. About 3,750 of the 5,064 main-source string lines (kind B: exception, validation, response and OpenAPI text) stay Vietnamese, which is most of what you called “messages”.

C. Translate A, B and C; keep only D. The backend is English everywhere except data. Vietnamese school users then receive English emails, pushes and spreadsheets, and the Excel header change needs a per-sheet check that the importer accepts the English header (the alias maps list English names first, but each sheet is checked). Adds phase 11.

Answer (2026-11-27): A – translate A and B; keep C and D. Phase 11 is therefore deferred.

D2. What happens to Vietnamese comments? Answered

Decided by you on 2026-11-27: “if the comments are violating the rules in AGENTS.md, remove it, otherwise translate them”. The plan reads this as follows (say so in chat before approving if a line is wrong):

Delete when the comment breaks Self-explaining code: it narrates the next statement (// 1. Validate the user, // Save to the database); it is a doc comment that only restates the name or signature of the class, method or field it sits on, with no contract, side effect or failure case; an @param or @return tag that repeats the parameter or type in words; a banner or divider that only names what the next member's name already says.

Translate, faithfully, keeping the “why” when the comment records a reason (a race, a security rule, a workaround, a lock or transaction order), states a contract (nullability, units, time zone, ordering, idempotency, failure cases, side effects), or documents a business rule or invariant. When in doubt, translate: a wrong deletion loses information that a wrong translation does not.

Also: a translated comment that contains a fully qualified {@link} gets an import and a simple name (AGENTS.md “Import types”). No commented-out code was found, so no rule is needed for it. The deletion rule applies to every file in the plan, not only to methods being edited, because the task is the translation itself (AGENTS.md Language: “unless the task is the translation itself”).

Answer (2026-11-27): Delete comments that violate AGENTS.md, translate the rest – the user's words as quoted above.

3. Phases

Each phase is independently reviewable and leaves the build green. Phases 2–9 follow the layers inside out (domain, application, infrastructure, interfaces); the tests of a package are translated in the same job as the package, because tests assert messages and must change with them.

Rules that every job follows

  1. Comments follow D2. The per-phase notes record how many comments were translated, deleted and left, and list the borderline ones, so deletions can be reviewed in the diff.
  2. Strings follow D1. A literal of a kept kind (C or D: emails, push text, Excel headers, seed data, import aliases, test fixtures) is left alone and recorded in the keep register (Implementation notes) with its file, line range and reason. A job never decides a kind silently: the register is how you review it.
  3. Terminology comes from the glossary built in job 1.3, so the same Vietnamese term is translated the same way everywhere, using the identifier the code already has.
  4. Structure is preserved. Placeholders ({}, %s, %d, {0}, {min} in validation messages), escapes and argument order stay; a concatenation keeps its operands in the same order (rephrase around them); no messages are merged or split. SQL -- comments inside text blocks are comments: translated, with the SQL itself unchanged.
  5. Method size. A translated comment inside a method body never takes more lines than the original (rewrap it; if it cannot fit without shortening, move it into the method's Javadoc). If deletions make a method on method-size-exemptions.txt short enough, remove its entry (the list may only shrink).
  6. Tests that assert a translated message change in the same job. Vietnamese fixtures (names, transcripts, INSERT values) stay. @DisplayName values and test comments are translated. Hand-written mocks are not converted to @Mock (that belongs to test-restructuring-plan).
  7. Unused code. A deleted comment can leave an import that only a {@link} used; remove such imports in the files the job edits.
  8. Standard check S, run at the end of every job: (a) the scanner reports 0 Vietnamese lines under the job's paths except sites on the keep register, including the unaccented word list; (b) the verifier reports no difference outside comments and string literals, equal literal counts and order, and equal placeholders; (c) ./gradlew compileJava compileTestJava; (d) the phase's test filter; (e) ./gradlew test --tests 'com.sep.vox.architecture.*'. After the scan, the job reads 20 random remaining comment or string lines of its paths to catch Vietnamese the word list missed, and reports the result.
