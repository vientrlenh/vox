Repository: vox · Branch: default · Written 2026-11-27 · Plan status: In progress

1,518 Java files (plus configuration, GraphQL schemas and resources) still contain Vietnamese: about 6,700 comment lines and 6,300 string-literal lines. This plan moves the code to English in 12 phases, each of which leaves the build green and can be reviewed (and merged) on its own. Messages: the texts the code writes to logs, returns to API clients and renders for end users (emails, push notifications, spreadsheet headers, order descriptions) become English; texts that are data (seed content, import column aliases, test fixtures) stay, and what exactly counts as a “message” is decision D1, widened by A2. Comments: a comment that breaks the AGENTS.md “Self-explaining code” rule is deleted, every other comment is translated faithfully (decision D2, already made).

D2. What happens to Vietnamese comments? Answered

Decided by you on 2026-11-27: “if the comments are violating the rules in AGENTS.md, remove it, otherwise translate them”. The plan reads this as follows (say so in chat before approving if a line is wrong):

Delete when the comment breaks Self-explaining code: it narrates the next statement (// 1. Validate the user, // Save to the database); it is a doc comment that only restates the name or signature of the class, method or field it sits on, with no contract, side effect or failure case; an @param or @return tag that repeats the parameter or type in words; a banner or divider that only names what the next member's name already says.

Translate, faithfully, keeping the “why” when the comment records a reason (a race, a security rule, a workaround, a lock or transaction order), states a contract (nullability, units, time zone, ordering, idempotency, failure cases, side effects), or documents a business rule or invariant. The deletion rule applies to every file in the plan, not only to methods being edited, because the task is the translation itself (AGENTS.md Language: “unless the task is the translation itself”).

3. Phases

Each phase is independently reviewable and leaves the build green. Phases 2–9 follow the layers inside out (domain, application, infrastructure, interfaces); the tests of a package are translated in the same job as the package, because tests assert messages and must change with them.

Rules that every job follows

  1. Comments follow D2. The per-phase notes record how many comments were translated, deleted and left, and list the borderline ones, so deletions can be reviewed in the diff.
  2. Strings follow D1, widened by A2. A literal of kind D (seed data, import aliases, test fixtures) is left alone and recorded in the keep register (Implementation notes) with its file, line range and reason. A literal of kind C (emails, push text, Excel headers, order descriptions) found before phase 11 is recorded the same way and translated in phase 11; the register rows that say “phase 11 is deferred” were written before A2. A job never decides a kind silently: the register is how you review it.
  3. Terminology comes from the glossary built in job 1.3, so the same Vietnamese term is translated the same way everywhere, using the identifier the code already has.
  4. Structure is preserved. Placeholders ({}, %s, %d, {0}, {min} in validation messages), escapes and argument order stay; a concatenation keeps its operands in the same order (rephrase around them); no messages are merged or split. SQL -- comments inside text blocks are comments: translated, with the SQL itself unchanged.
  5. Method size. A translated comment inside a method body never takes more lines than the original (rewrap it; if it cannot fit without shortening, move it into the method's Javadoc). If deletions make a method on method-size-exemptions.txt short enough, remove its entry (the list may only shrink).
  6. Tests that assert a translated message change in the same job. Vietnamese fixtures (names, transcripts, INSERT values) stay. @DisplayName values and test comments are translated. Hand-written mocks are not converted to @Mock (that belongs to test-restructuring-plan).
  7. Unused code. A deleted comment can leave an import that only a {@link} used; remove such imports in the files the job edits.
  8. Standard check S, run at the end of every job: (a) the scanner reports 0 Vietnamese lines under the job's paths except sites on the keep register, including the unaccented word list; (b) the verifier reports no difference outside comments and string literals, equal literal counts and order, and equal placeholders; (c) ./gradlew compileJava compileTestJava; (d) the phase's test filter; (e) ./gradlew test --tests 'com.sep.vox.architecture.*'. After the scan, the job reads 20 random remaining comment or string lines of its paths to catch Vietnamese the word list missed, and reports the result.
