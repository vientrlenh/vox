2. Rules for choosing the type

  1. Write the exact type the compiler inferred, except for collections (rule 2). A var holding an Integer becomes Integer, never int, so a null does not turn into an NPE.
  2. Collections: use the interface when the code only uses interface methods, for example List<T> x = new ArrayList<>(y). (Subject to decision D4.)
  3. Manual cases that a tool cannot always write for you: intersection types (var x = cond ? a : b), anonymous classes, captured wildcards, long stream chains (check what the terminal operation returns), and Map.Entry<K, V> in for loops.
  4. Touch nothing else on the line. Keep the declaration on one line, add only the imports it needs, do not reformat.
  5. Method-length limits (25 lines) are not affected as long as declarations stay on one line.
  6. Tests (phase 5): same rules. Typical cases are var result = useCase.execute(...), ArgumentCaptor<T> and values returned by mock(...). Change only the declared type: do not migrate hand-written mock(...) tests to MockitoExtension (AGENTS.md says not to do that as a drive-by).

6. Verification after every batch

  1. ./gradlew compileJava (phases 1–4) or ./gradlew compileTestJava (phase 5)
  2. ./gradlew test --tests '*LayeredArchitectureTests' (new imports must not break a layer rule)
  3. The narrowest relevant filter, for example ./gradlew test --tests '*Exam*' for batch 2b. In phase 5, run the test classes you edited.
  4. Nothing left in the batch scope: 
    grep -rE '\bvar [a-z]' src/main/java/com/sep/vox/<path> --include='*.java'
    should print nothing (use src/test/java/com/sep/vox/<path> in phase 5).
  5. Review git diff: only var lines and imports should differ (plus translated or removed comments, as decided in D2). Every removed comment is listed in the batch report with the reason.

At the end of each phase, run the full ./gradlew test. Run ./gradlew integrationTest once at the very end (needs Docker); in phase 5 it is the only way to run the @RepositoryTest and @IntegrationTest classes you edited. Anything not run will be stated plainly in the report.
