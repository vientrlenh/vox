Migrate hand-written constructors and loggers to @RequiredArgsConstructor and @Slf4j

Repository: vox · Branch: default · Written 2026-11-22 · Plan status: Done

Replace the constructors that only assign their parameters to fields, and the hand-written LoggerFactory.getLogger(...) fields, with @RequiredArgsConstructor and @Slf4j. Measured today: 840 classes with an assignment-only constructor and 111 classes with a hand-written logger, which is 864 files because 87 have both. Neither annotation is used anywhere in src/main yet. The change must not alter behaviour: every constructor signature stays identical (proved by a before/after snapshot of all constructors in the compiled classes) and every logger keeps the name of its class.

1.3 Lombok behaviour this plan relies on

Read on 2026-11-22: projectlombok.org/features/constructor, /features/log, /features/configuration. Lombok is not a Spring API, so Spring Boot 4.1 / Spring Framework 7 docs were not needed: each class keeps exactly one public constructor with the same signature, so wiring is unchanged (the snapshot in 1.8 proves it).

  • @RequiredArgsConstructor: “All non-initialized final fields get a parameter”, and “The order of the parameters match the order in which the fields appear in your class.” Static fields are skipped. An explicit constructor does not stop generation, and a clash is a compile error, so each explicit constructor must be deleted in the same edit.
  • @Slf4j creates private static final org.slf4j.Logger log = org.slf4j.LoggerFactory.getLogger(Foo.class);. The default field name is log and the logger name is the annotated class.
  • lombok.copyableAnnotations exists and defaults to an empty list, so field annotations such as @Value and @Qualifier are not copied onto generated constructor parameters unless a lombok.config says so.
  • Not stated by the docs: the default access level of the generated constructor. Job 1.2 checks it with javap before any wide edit.

3. Phases

Each phase is independently reviewable and leaves the build green. Phases 2 to 13 are each a mechanical script run followed by a review of git diff --stat and a sample of diffs; they never change a line of logic.

Migration rules every job follows

R1 Constructor. A class qualifies when it has exactly one constructor, it is public, its parameters carry no annotation, its body is only this.x = x; for every parameter, and those fields are exactly its private final fields without initializer. Delete the constructor, add @RequiredArgsConstructor and import lombok.RequiredArgsConstructor;. Anything else keeps its constructor.

R2 Annotation placement. Spring stereotypes first (@Service, @Repository, ...), then @RequiredArgsConstructor, then @Slf4j. Put the Lombok imports in alphabetical order inside the existing non-java, non-com.sep import group, as the entities do. Leave no stray blank lines where the constructor was.

R3 Parameter order. Lombok orders parameters by field declaration order. Where the hand-written parameter order differs (the 5 classes in 1.7), move the field declarations into the constructor's parameter order. Never change the parameter order, because tests and @InjectMocks depend on it. A renamed parameter (RubricController) disappears with the constructor.

R4 Logger. Delete the Logger field, add @Slf4j and import lombok.extern.slf4j.Slf4j;, rename LOGGER. to log. in the class, and delete org.slf4j.Logger and org.slf4j.LoggerFactory imports that are no longer used. The logger name stays the class (1.6). Do not add a lombok.config (that would be a file outside the AGENTS.md patterns).

R5 Comments (D3). Translate every Vietnamese comment on a line this change edits or deletes into English and keep its meaning and its “why”. A comment on a deleted constructor or parameter moves to the class or the matching field. With D3 = B also translate every other Vietnamese comment in the file. Leave user-facing string literals as they are.

R6 Nothing else. No reformatting, renames, import reordering beyond R2, or logic edits. Test files are not edited.
