Test restructuring plan

Repository: vox · Branch: refactor/rewritten · Written 2026-11-19 · Plan status: In progress – phases 4 and 5 are partly done (section 11)

Goal: make the test suite fast and honest about what each test needs. Controllers use @WebMvcTest, use cases use @ExtendWith(MockitoExtension.class), repositories use @DataJpaTest, and tests are split into unit (no Docker) and integration (Docker or full Spring context) suites. The structure is modelled on the sibling repository tsoft, which already runs this setup.

Implemented in commit 57764f02. The sections below are the original proposal, kept as written. Where the result differs from it, or an item is only partly done, section 11 says so.

3. Decisions for you

D1. How to separate the suites Answered

A. JUnit tag (recommended): @Tag("integration") via two composed annotations; test excludes the tag, a new integrationTest task includes it. This is what tsoft does. One source set, trivial to adopt.

B. Separate source set (src/integrationTest/java): the boundary is physical and cannot be forgotten, but it moves ~50 files, needs shared test-support code on both classpaths, and fights IDE defaults.

Weakness of A: a test that forgets the tag silently runs in the fast suite. I propose an ArchUnit rule to close that gap (see Phase 3).

Answer: A, the JUnit tag. @RepositoryTest and @IntegrationTest carry the integration tag and TestSuiteSeparationTests guards it. Resolved by the implementation in commit 57764f02; the original answer was not recorded.

D2. Replace ContainerTestConfig with a @ServiceConnection bean? Answered

Yes (recommended): a @TestConfiguration with a PostgreSQLContainer bean. No inheritance, no static initializer, and the same bean can power a local dev launcher. Need to confirm in Phase 2 whether @DataJpaTest also needs @AutoConfigureTestDatabase(replace = NONE) with Spring Boot 4.1.

No: keep the abstract base class and only add tags. Smaller change, but 48 test classes keep depending on inheritance.

Answer: Yes, but implemented differently: ContainerTestConfig is gone and TestcontainersConfiguration starts the container in a static initializer with a DynamicPropertyRegistrar, not as a @ServiceConnection bean (see section 11). Resolved by the implementation in commit 57764f02; the original answer was not recorded.

D3. Fix the Testcontainers version mix? Answered

Yes: replace the pinned postgresql:1.21.4 and junit-jupiter:2.0.5 with the 2.x artifacts (testcontainers-postgresql, testcontainers-junit-jupiter) and let the Spring Boot BOM manage the version. AGENTS.md requires approval before changing pinned versions, so this is an explicit ask. Keep the image pinned to postgres:18 (tsoft's postgres:latest is a flaw I do not want to copy).

Answer: Yes. build.gradle uses testcontainers-postgresql and testcontainers-junit-jupiter with no pinned version. Resolved by the implementation in commit 57764f02; the original answer was not recorded.

D4. Security in controller slices Answered

Testing @PreAuthorize means importing SecurityConfig (or a test security config) and probably adding spring-boot-starter-security-test for @WithMockUser. Both touch security configuration or dependencies, which AGENTS.md lists under "ask first".

Recommended: add a test-only security configuration inside src/test and do not modify SecurityConfig itself. Add the security test starter only if needed, with your approval.

Answer: The recommended approach: test-only WebMvcTestSecurityConfiguration and GraphQlTestSecurityConfiguration under src/test. Resolved by the implementation in commit 57764f02; the original answer was not recorded.

D5. GraphQL controllers Answered

@WebMvcTest does not apply to GraphQL. Options:

A. (recommended) Leave the 12 direct-call tests as unit tests and add @GraphQlTest only where schema binding or authorization matters (GradingSchemaBindingTests, the *AuthorizationBoundaryTests).

B. Convert all 12 to @GraphQlTest. More coverage of schema binding, more effort, slower.

Answer: A. Eight *AuthorizationGraphQlTests classes use @GraphQlControllerTest; GradingSchemaBindingTests was not converted (see section 11). Resolved by the implementation in commit 57764f02; the original answer was not recorded.

D6. Migration strategy for existing tests Answered

A. Phased, by category (recommended): tag the Docker-dependent tests once (about 50 files, mechanical), convert controllers by priority, migrate use cases to MockitoExtension only when a file is otherwise being edited.

B. Big bang: convert all 168 use case tests at once. Strict stubs will fail tests that stub things they never use, so this risks a large, noisy diff and many unrelated fixes. Not recommended.

Answer: A, phased. Only usecase/auth is converted so far, 8 of 9 tests. Resolved by the implementation in commit 57764f02; the original answer was not recorded.

D7. AGENTS.md update Answered

Update it in the same change as Phase 1 so the rules and the repository never disagree. Proposed wording is in section 6.

Answer: Yes. AGENTS.md has the new Commands and Testing sections. Resolved by the implementation in commit 57764f02; the original answer was not recorded.

      5. Proposed configuration

      build.gradle (Phase 1)

      tasks.withType(Test).configureEach {
    systemProperty 'user.timezone', 'Asia/Ho_Chi_Minh'
    maxHeapSize = '4g'
}

tasks.named('test') {
    description = 'Runs unit and web-slice tests (no Docker)'
    useJUnitPlatform { excludeTags 'integration' }
}

def integrationTest = tasks.register('integrationTest', Test) {
    description = 'Runs tests that need Docker or the full Spring context'
    group = 'verification'
    testClassesDirs = sourceSets.test.output.classesDirs
    classpath = sourceSets.test.runtimeClasspath
    useJUnitPlatform { includeTags 'integration' }
    shouldRunAfter tasks.named('test')
}

tasks.named('check') { dependsOn integrationTest }

      Composed annotations (Phase 2)

      @Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Tag("integration")
@DataJpaTest
@Import(TestcontainersConfiguration.class)
@ActiveProfiles("test")
public @interface RepositoryTest { }

@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Tag("integration")
@SpringBootTest
@Import(TestcontainersConfiguration.class)
@ActiveProfiles("test")
public @interface IntegrationTest { }

@TestConfiguration(proxyBeanMethods = false)
public class TestcontainersConfiguration {
    @Bean
    @ServiceConnection
    PostgreSQLContainer postgresContainer() {
        return new PostgreSQLContainer(DockerImageName.parse("postgres:18"));
    }
}

      Sketch only: exact imports and the need for @AutoConfigureTestDatabase are confirmed against the Spring Boot 4.1 documentation in Phase 2.

      Tag guardrail (Phase 3, ArchUnit)

      classes()
    .that().areAnnotatedWith(SpringBootTest.class)
    .or().areAnnotatedWith(DataJpaTest.class)
    .should().beAnnotatedWith(Tag.class)   // directly, or via the composed annotations
    .because("Docker-dependent tests must run only in integrationTest");

      The composed annotations hide the base annotations from a direct check, so the final rule will be written against what ArchUnit can actually see. If it cannot be expressed reliably, the fallback is a plain test that scans test sources for raw @SpringBootTest / @DataJpaTest, like PagingConventionTests does.

      6. AGENTS.md changes (proposed)

      • Commands: ./gradlew test = unit and web-slice tests, no Docker; ./gradlew integrationTest = Docker tests; ./gradlew check = both. Replace "needs Docker (Testcontainers Postgres 18)" on the test line.
      • Testing:
        • Use cases and services: @ExtendWith(MockitoExtension.class).
        • REST controllers: @WebMvcTest with MockMvcTester; every role-protected endpoint gets an authorization test.
        • Repositories and queries: @RepositoryTest; full context: @IntegrationTest. Never use raw @SpringBootTest / @DataJpaTest.
        • Class suffix: XxxTests for unit, XxxIntegrationTests for integration (confirm if you want the suffix rule at all).
      • Finishing a task: verify with compileJava and the narrowest --tests filter; run integrationTest only when Docker is available.

      Differences from the proposal

      • TestcontainersConfiguration starts the container in a static initializer and registers the connection with a DynamicPropertyRegistrar. It is not a @ServiceConnection bean, because Spring closes container beans when a cached context is destroyed and that would stop the database under the other contexts. The consequence is that all contexts share one database, so a test that commits data must clean up after itself.
      • @RepositoryTest also sets @AutoConfigureTestDatabase(replace = NONE).
      • All phases landed in one commit, so the per-downgrade commits proposed in Phase 3 do not exist.
      • The XxxIntegrationTests suffix was dropped; every test class is still named XxxTests.
